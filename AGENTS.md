## Godot Headers for GDExtension Integration
- To integrate as a godot gdextension, godot provides a set of files that have been copied into `godot_headers`.
- `godot_headers/extension_api.json` - a comprehensive metadata file generated by the Godot Engine that describes its entire scripting API (classes, methods, properties, signals, and enums) for use with GDExtension. It acts as a bridge between the core engine and native C++ code (or other languages), allowing external libraries to interact with Godot's built-in functionality.
- `godot_headers/godot/gdextension_interface.h` - the foundational C header file that defines the GDExtension interface for Godot 4. It acts as the "bridge" or ABI (Application Binary Interface) between the Godot Engine and native libraries (such as C++ or Rust).
- These files are refreshed by exporting them from the godot binary by executing `make update_godot_headers_from_binary`.
- Do not directly modify any files that have `.gen.` in the filename; all of these files are codegen files. Instead, make changes to the `*.tmpl` template files under the `cmd/generate` directory and then propagate those changes into the `*.gen.*` files with `make generate`.
- Read through and cache the official GDExtension C Example documentation at https://docs.godotengine.org/en/stable/tutorials/scripting/gdextension/gdextension_c_example.html 

## Repository Structure
- `cmd/main.go` - a cli tool for managing codegen in the project.
  - `cmd/extensionapiparser` - JSON parser for `godot_headers/extension_api.json` to generate Go code at `pkg/builtin/*.gen.go` and C code at `pkg/ffi/ffi_wrapper.gen.*`.
  - `cmd/gdextensionparser` - C header parser for `godot_headers/godot/gdextension_interface.h` to generate Go code for `pkg/**/*.gen.go` to represent godot primitives in Go.
- `godot_headers/` -  the necessary C header files (.h) and metadata for developing a gdextension.
- `pkg/` - Go packages. Listed below are a few key packages:
  - `pkg/ffi/` - Foreign Function Interface wrappers (C/Go bridge)
  - `pkg/builtin/` - Generated Go types for Godot built-in types (Vector2, Vector3, etc.)
  - `pkg/core/` - Core binding functionality and method binding reflection
  - `pkg/gdclassimpl/` - Generated implementations for Godot classes
  - `pkg/gdclassinit/` - Class initialization and registration code
  - `pkg/constant/` - Godot constants and enums
  - `pkg/nativestructure/` - Native C structure definitions
  - `pkg/gdutilfunc/` - Generated utility functions

## Testing
- Use `make test` to run the project's test suite.
- Fix any test or type errors until the whole suite is green.
- Add or update tests for the code you change, even if nobody asked.

### Tooling
```bash
# Generate test project files for first time (may fail initially)
GODOT=/path/to/godot make ci_gen_test_project_files

# Run tests
GODOT=/path/to/godot make test

# Interactive testing with Godot editor
GODOT=/path/to/godot make interactive_test

# Open demo project in Godot editor
make open_demo_in_editor
```

# Install dependencies

## Architecture Overview
This project provides Go bindings for Godot 4.3+ through the GDExtension API using cgo.

**Build System:**
- Uses Go's c-shared buildmode to create dynamic libraries
- Outputs platform-specific binaries to `test/demo/lib/`
- Supports Linux (.so), Windows (.dll), and macOS (.framework)
- Debug builds include extensive debugging symbols and flags

### Go-GDScript Mapping
The project handles Go-to-GDScript language differences:

**Class Inheritance:** Uses struct embedding instead of classical inheritance
```go
type PlayerCharacter struct {
    CharacterBody2DImpl  // Embeds to simulate inheritance
}
```

**Virtual Methods:** Uses `V_` prefix convention for virtual function registration

**Type Mappings:**
- `int` → `int64`
- `float` → `float64` 
- `String` → Godot `String` type with helper conversions to Go `string`
- Built-in vector types map directly (Vector2, Vector3, etc.)

### Testing and Development
The project includes a test demo at `test/demo/` that:
- Acts as both test suite and example usage
- Requires Godot binary for execution
- Uses extensive Go runtime debugging flags for development
- Builds as a GDExtension library that Godot loads

### Commit Conventions
- Follow Conventional Commits: `type: subject` — use `feat:` for features, `fix:` for bug fixes, `chore:` for maintenance, `docs:` for documentation, `refactor:` for non-behavior changes (the types in this repo's history)
- When a commit merges a GitHub PR, append `(#NNN)` to the subject (e.g. `feat: update to godot 4.7.2 (#128)`)
- Keep the subject imperative, lowercase, under ~72 chars

### Requirements
- Go 1.25.0+
- Godot 4.5 binary
- clang-format for C code formatting
- goimports for Go code formatting
- gcc for compilation

The project is experimental and under active development with API subject to change.
